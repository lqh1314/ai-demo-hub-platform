# 需求：接线机器人 + 电销工作台 全链路平台（To-B SaaS 获客）

## 问题陈述
- 业务：To-B SaaS 产品获客。潜在客户通过官网/广告/400 热线等呼入咨询。
- 现状痛点：人工接线覆盖不全（漏接、非工作时间无人接）、线索信息靠手记易丢失、意向客户分配不及时、
  坐席跟进过程不透明、管理者看不清线索→接通→转化漏斗与坐席产能。
- 目标：AI 接线机器人 7x24 承接呼入、多轮对话答疑并识别意向、自动留资建档与派单；
  电销坐席在统一工作台完成来电弹屏、跟进、外呼与商机推进；管理者通过报表掌控全链路。

## 成功画面
客户呼入即被 AI 秒接并自然对话、解答 FAQ、识别意向后自动留资并按规则派给合适坐席；
坐席工作台实时弹屏，展示客户画像、历史、实时转写与 AI 小结，一键外呼/跟进、推进商机阶段；
主管在管理端看到线索量、接通率、转化率、坐席工作量与漏斗，可做分配、质检与干预。全流程数据可追溯。

## 标准业务主流程（Flow A）
呼入 → AI 接线（ASR→对话编排/知识库→TTS 应答）→ 意向识别 → 留资建档 / 转人工
→ 线索按规则派单到技能组/坐席 → 坐席工作台（来电弹屏、画像、实时转写、AI 小结、待办）
→ 外呼/跟进记录 → 商机阶段推进（新线索→已联系→意向→方案→谈判→赢单/输单）→ 报表与质检。

## 范围
### In Scope（一次做全）
1. AI 接线机器人：呼入应答、多轮对话编排、知识库 FAQ、意向识别、留资、转人工；机器人话术/知识库配置后台
2. 电销工作台：坐席状态、来电弹屏、客户画像、实时转写、AI 小结、待办、外呼、跟进、时间线
3. CRM 主线：客户、联系人、商机、通话记录、跟进记录、任务、阶段漏斗
4. 智能派单/队列：技能组、坐席状态机、分配规则（轮询/最少负载/技能匹配）
5. 外呼：手动点呼、批量外呼任务、简化预测式拨号
6. 管理端：组织/部门/账号/角色、报表大盘、质检、系统配置
7. 轻量合同/回款登记；营销触达（短信/邮件/企微）任务与通道适配
8. 开放 API / Webhook；第三方 IM 通知适配占位
9. 多租户字段（tenant_id）在数据层预留，默认单组织；响应式 H5

### Out of Scope（本环境不交付，仅预留/说明）
- 真实运营商线路开户、真实号码/资质、SIP 落地：提供适配层与沙箱模拟，需用户提供账号后切真
- 商用 ASR/TTS/大模型：内置沙箱实现与接口，密钥配置后可接真实服务
- 真实短信/邮件/支付网关发码与扣款：沙箱通道 + 接口预留
- 原生 iOS/Android App 编译与上架：以响应式 H5 替代
- 面向外部客户的多租户商业化开通/计费流程：仅预留 tenant_id 与扩展位

## 技术约束
- 规模：200+ 坐席，需实时坐席/通话态（WebSocket），关键链路分页+索引+缓存，可水平扩展
- 安全：鉴权与越权防护、输入校验、审计日志、敏感信息脱敏、通话数据合规留存
- 外部依赖一律走适配层，核心业务不绑定单一供应商；沙箱实现保证离线可完整运行与演示
- 交付需可一键启动、可测试、可复现；提供部署 runbook（含数据库回滚）

## 技术栈（待闸门 A 确认）
- 前端：React 18 + TypeScript + Vite + Ant Design + Zustand/React Query + ECharts + 原生 WebSocket/Socket.IO-client；Vitest + RTL
- 后端：Node 20 + NestJS（TypeScript）+ Socket.IO Gateway；Jest + Supertest
- 数据库：PostgreSQL 15（Prisma ORM，含迁移）+ Redis 7（坐席态/队列/缓存/BullMQ）
- 鉴权：JWT(access+refresh) + bcrypt + RBAC 守卫 + 审计中间件
- 语音/AI：Telephony/ASR/TTS/LLM Provider 适配层 + Sandbox Provider
- 测试：后端 Jest、前端 Vitest、Playwright 冒烟；新业务逻辑覆盖率目标 80%+
- 部署：Docker Compose 一键起（pg/redis/api/web）；GitHub 仓库托管；前端可选 EdgeOne Pages；含回滚 runbook
